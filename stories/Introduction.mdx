# Welcome to Constructor's Checkout UI

Headless primitives for building multi-step checkout on top of Stripe. The library gives you the state machine, session lifecycle, storage, and Stripe surface — your app composes the UI.

## Where to go next

- **[Integration Guide](./?path=/docs/general-integration-guide--docs)** — install, wire up, and ship a working flow
- **[Routing](./?path=/docs/general-routing--docs)** — real-world adapter snippets for React Router, Next.js App Router, TanStack Router, and vanilla `window.location`
- **[Components / CheckoutFlow](./?path=/docs/components-checkoutflow--docs)** — the basic shapes: single-page multi-step, express Buy Now, guest, with-login, routed, persistence
- **[Components / CheckoutFlow / Advanced](./?path=/story/components-checkoutflow-advanced)** — obscure but real patterns: mid-flow add-to-cart, session recovery, custom fulfillment UI, backend storage, multi-instance, and more

## Three integration paths, one core

| Path | Best for | Entry |
|---|---|---|
| React | React apps with the full flow | `<CheckoutFlowProvider>` + `useCheckoutFlow()` |
| Vanilla JS (npm) | Non-React SPAs or custom UIs | `new CheckoutFlow(config)` |
| Standalone bundle | Server-rendered sites, `<script>` tags | `window.CioCheckout.resume(config)` |

All three wrap the same framework-agnostic `createCheckoutFlow(config)` core.

## What the library owns

- Multi-step state machine (start / next / back / goTo / guards / optional steps)
- Session lifecycle (create / update / expire / recreate) with a serialization queue for payment integrity
- Storage adapter interface (default sessionStorage; merchants provide backend adapters for B2B / multi-device pause-resume)
- Router adapter interface (URL sync for routed multi-step; MPA works via full-page navigation + storage rehydrate)
- Default Stripe surface (`<CheckoutStripeStep>`) and default fulfillment UI (`<CheckoutFulfillmentStep>`)
- Typed events for analytics + error handling

## What you own

- The button that opens checkout — style, placement, visibility gating
- Cart, address, login, review, confirmation views (or any custom steps)
- Modal vs. inline vs. routed presentation
- Analytics wiring via the `onEvent` callback
