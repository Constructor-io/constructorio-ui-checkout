# CioCheckout

A React component that wraps Stripe's Embedded Checkout into a drop-in checkout experience with modal/inline display modes, fulfillment verification, and lifecycle callbacks.

## Session

The `session` prop tells the component how to get the Stripe Checkout Session credentials
(`clientSecret` and `publishableKey`). You can provide it in two ways:

### Direct object

Pass the session response directly if you already have it:

```tsx
<CioCheckout
  session={{
    clientSecret: 'cs_test_...',
    publishableKey: 'pk_test_...',
  }}
/>
```

### Async function

Pass a function that fetches the session from your backend. The function is called
when the customer clicks the checkout trigger:

```tsx
<CioCheckout
  session={async () => {
    const res = await fetch('/api/checkout-session', { method: 'POST' });
    return res.json(); // must return { clientSecret, publishableKey }
  }}
/>
```

### Registry pattern

For non-React or multi-library setups, you can register a session globally once
and omit the `session` prop entirely:

```ts
import { checkoutRegistry } from '@constructor-io/constructorio-ui-checkout';

checkoutRegistry.register(async () => {
  const res = await fetch('/api/checkout-session', { method: 'POST' });
  return res.json();
});
```

```tsx
// No session prop needed — picks it up from the registry
<CioCheckout />
```

### Disabling the redirect after payment

By default, Stripe redirects the customer to a `return_url` after payment completes. This library
is designed to handle completion in-place (closing the modal/inline checkout, running fulfillment
verification, etc.) using the `onComplete` callback — so you should **disable the redirect** when
creating the Checkout Session on your backend:

```js
// On your backend
const session = await stripe.checkout.sessions.create({
  ui_mode: 'embedded',
  redirect_on_completion: 'never', // prevents redirect, fires onComplete instead
  // return_url: '...',            // remove this if present
  line_items: [{ price: 'price_...', quantity: 1 }],
  mode: 'payment',
});
```

Use `'never'` for the best experience with this library. If you need to support redirect-based
payment methods, use `'if_required'` and provide a `return_url` as a fallback.

## Branding & Appearance

Stripe Embedded Checkout does **not** support client-side theming or an `appearance` API.
To brand the checkout UI, configure these settings in your **Stripe Dashboard** under
**Settings > Branding**:

<table>
  <thead>
    <tr>
      <th>Setting</th>
      <th>What it controls</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>Logo</strong></td>
      <td>Displayed at the top of the checkout form</td>
    </tr>
    <tr>
      <td><strong>Icon</strong></td>
      <td>Small icon / favicon</td>
    </tr>
    <tr>
      <td><strong>Brand color</strong></td>
      <td>Applied to buttons and accent elements</td>
    </tr>
    <tr>
      <td><strong>Accent color</strong></td>
      <td>Used for links and highlights</td>
    </tr>
  </tbody>
</table>

These settings apply **globally** to all Embedded Checkout sessions for your Stripe account.
There is no per-session or per-component customization — no custom CSS, fonts, or layout overrides
are available.

> For full control over checkout styling, Stripe offers the **Payment Element API**
> (using Payment Intents with `pi_` keys instead of Checkout Sessions), which supports the
> `appearance` option. That is a different integration path and is not covered by this library.

## Stripe Callbacks

### `onShippingDetailsChange`

Called when the customer completes the shipping details form inside Stripe's checkout UI.

**Prerequisite:** Your backend must create the Checkout Session with
`permissions.update.shipping_details` set to `'server_only'`.

```tsx
<CioCheckout
  session={mySession}
  onShippingDetailsChange={async (event) => {
    // event.checkoutSessionId — the Stripe session ID
    // event.shippingDetails — { name, address: { country, line1, ... } }

    const res = await fetch('/api/update-shipping', {
      method: 'POST',
      body: JSON.stringify({
        sessionId: event.checkoutSessionId,
        address: event.shippingDetails.address,
      }),
    });
    const data = await res.json();

    if (!data.ok) {
      return { type: 'reject', errorMessage: data.reason };
    }
    return { type: 'accept' };
  }}
/>
```

### `onLineItemsChange`

Called when the customer adds, removes, or modifies a line item inside Stripe's checkout UI.

**Prerequisite:** Your backend must create the Checkout Session with
`permissions.update.line_items` set to `'server_only'`.

```tsx
<CioCheckout
  session={mySession}
  onLineItemsChange={async (event) => {
    // event.checkoutSessionId — the Stripe session ID
    // event.lineItems — array of { id, quantity, price, ... }

    const res = await fetch('/api/update-line-items', {
      method: 'POST',
      body: JSON.stringify({
        sessionId: event.checkoutSessionId,
        lineItems: event.lineItems,
      }),
    });
    const data = await res.json();

    if (!data.ok) {
      return { type: 'reject', errorMessage: data.reason };
    }
    return { type: 'accept' };
  }}
/>
```

### How it works

1. Your backend creates a Checkout Session with the relevant permission set to `'server_only'`
2. The customer changes shipping details or line items in Stripe's UI
3. Your callback fires client-side with the event data
4. Inside the callback, you call your backend to recalculate (shipping options, totals, etc.)
5. Your backend updates the Checkout Session via the Stripe API
6. You return `{ type: 'accept' }` or `{ type: 'reject', errorMessage: '...' }` to Stripe

See [Stripe docs: Custom Shipping Options](https://docs.stripe.com/payments/checkout/custom-shipping-options) for more details.
