# Welcome to Constructor's Checkout UI

Headless primitives for building multi-step checkout on top of Stripe. The library gives you the state machine, session lifecycle, storage, and Stripe surface — your app composes the UI.

## Three integration paths, one core

| Path              | Best for                               | Entry                                                          |
| ----------------- | -------------------------------------- | -------------------------------------------------------------- |
| React             | React apps with the full flow          | `<CioCheckoutProvider provider="stripe">` + `useCioCheckout()` |
| Vanilla JS (npm)  | Non-React SPAs or custom UIs           | `createCheckoutFlow(config)`                                   |
| Standalone bundle | Server-rendered sites, `<script>` tags | `window.CioCheckout.resume(config)`                            |

All three wrap the same framework-agnostic `createCheckoutFlow(config)` core.

## What the library owns

- Multi-step state machine (start / next / back / goTo / guards / optional steps)
- Session lifecycle (create / update / expire / recreate) with a serialization queue for payment integrity
- Storage adapter interface (opt-in — pass `storage` + `storageKey` to enable; `createSessionStorageAdapter()` gives local persistence, or supply your own backend adapter for B2B / multi-device pause-resume). The standalone `CioCheckout.resume()` entry injects the sessionStorage adapter automatically; `CioCheckoutProvider` and `createCheckoutFlow(config)` do not — persistence is opt-in.
- Router adapter interface (URL sync for routed multi-step; MPA works via full-page navigation + storage rehydrate)
- Default Stripe surface (`<CioStripePaymentStep>`) and default fulfillment UI (`<CioFulfillmentStep>`)
- Typed events for analytics + error handling

## What you own

- The button that opens checkout — style, placement, visibility gating
- Cart, address, login, review, confirmation views (or any custom steps)
- Modal vs. inline vs. routed presentation
- Analytics wiring via the `onEvent` callback
