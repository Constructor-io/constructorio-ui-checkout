# Integration Guide

Headless primitives for building multi-step checkout on top of Stripe. The library gives you the state machine, session lifecycle, storage, and Stripe surface — your app composes the UI.

## Three integration paths, one core

- **React** — `<CioCheckoutProvider provider="stripe">` + `useCioCheckout()` + `<CioCheckoutStep>` + `<CioStripePaymentStep>` / `<CioFulfillmentStep>`
- **Vanilla JS (npm)** — `createCheckoutFlow(config)` from `@constructor-io/constructorio-ui-checkout`
- **Standalone bundle** — `<script>` tag exposes `window.CioCheckout` with the same class

All three wrap the framework-agnostic `createCheckoutFlow(config)` core.

## Quick start (React)

```tsx
import {
  CioCheckoutProvider,
  CioCheckoutStep,
  CioStripePaymentStep,
  CioFulfillmentStep,
  PAYMENT_STEP,
  useCioCheckout,
} from '@constructor-io/constructorio-ui-checkout';

function App() {
  return (
    <CioCheckoutProvider
      provider="stripe"
      steps={[
        { id: 'cart' },
        { id: 'address' },
        { id: PAYMENT_STEP },
        { id: 'fulfill' },
        { id: 'done' },
      ]}
      onCreateSession={() => fetch('/api/checkout').then(r => r.json())}
      onEvent={(event) => console.log(event)}
    >
      <StartButton />
      <CioCheckoutStep id="cart"><MyCart /></CioCheckoutStep>
      <CioCheckoutStep id="address"><MyAddressForm /></CioCheckoutStep>
      <CioCheckoutStep id={PAYMENT_STEP}>
        <CioStripePaymentStep uiMode="form" />
      </CioCheckoutStep>
      <CioCheckoutStep id="fulfill">
        <CioFulfillmentStep
          onFulfill={() => fetch('/api/verify').then(r => r.json())}
        />
      </CioCheckoutStep>
      <CioCheckoutStep id="done"><MyConfirmation /></CioCheckoutStep>
    </CioCheckoutProvider>
  );
}

function StartButton() {
  const flow = useCioCheckout();
  if (flow.state.currentStepId !== null) return null;
  return <button onClick={() => flow.start()}>Checkout</button>;
}
```

## When to show the trigger

The old library shipped `<CheckoutTrigger>`, `trigger`, `triggerLabel`, and `triggerWhen`. The new design leaves the button to you — place it anywhere, style it any way, and gate it on any state:

```tsx
function BuyButton() {
  const flow = useCioCheckout();
  const cart = useMyCartStore();
  if (cart.items.length === 0) return null;
  if (flow.state.sessionStatus === 'creating') return <Spinner />;
  return <button onClick={() => flow.start()}>Buy now</button>;
}
```

## Modal vs. inline

There is no `displayMode` prop — wrap the `stripe` step in your own modal or render it inline:

```tsx
<CioCheckoutStep id={PAYMENT_STEP}>
  <MyModal open>
    <CioStripePaymentStep />
  </MyModal>
</CioCheckoutStep>
```

## Routed multi-step

Pass a `router` adapter and give each step a `path`. The library keeps URL and state in sync, so browser back, refresh, and deep links all work:

```tsx
<CioCheckoutProvider
  provider="stripe"
  steps={[
    { id: 'cart', path: '/cart' },
    { id: 'address', path: '/checkout/address' },
    { id: PAYMENT_STEP, path: '/checkout/payment' },
  ]}
  router={{
    push: (path) => navigate(path),
    getCurrentPath: () => location.pathname,
    subscribe: (cb) => registerNavListener(cb),
  }}
  onCreateSession={...}
>
  ...
</CioCheckoutProvider>
```

Steps with a `path` participate in URL sync; steps without one render inline/modal.

## Persistence and resume

Pass a `storage` adapter and `storageKey` to auto-save state and hydrate on the next mount. The default `createSessionStorageAdapter()` survives page reloads in the same tab. For B2B pause/resume (approver on a different device), supply a custom async adapter backed by your server.

```tsx
<CioCheckoutProvider
  provider="stripe"
  storage={createSessionStorageAdapter()}
  storageKey={`user-${userId}`}
  ...
/>
```

## Cart sync

Two options, both funnel through `onUpdateSession`:

- `flow.syncCart(items)` — explicit, immediate
- Reactive `cart={items}` prop on the Provider — debounced (default 400ms)

## Vanilla JS

```js
import { createCheckoutFlow } from '@constructor-io/constructorio-ui-checkout';

const flow = createCheckoutFlow({
  provider: 'stripe',
  steps: [{ id: 'createSession' }, { id: 'payment' }],
  onCreateSession: () => fetch('/api/session').then(r => r.json()),
});

flow.subscribe((state) => renderMyUI(state));
await flow.start();
```

## Standalone bundle

```html
<script src="/path/to/constructorio-ui-checkout.standalone.js"></script>
<script>
  const flow = CioCheckout.resume({
    provider: 'stripe',
    steps: [{ id: 'cart', path: '/cart' }, { id: 'payment', path: '/pay' }],
    onCreateSession: () => fetch('/api/session').then(r => r.json()),
    router: {
      push: (p) => (window.location.href = p),
      getCurrentPath: () => window.location.pathname,
    },
    storageKey: 'user-123',
  });
  flow.start();
</script>
```

`resume()` creates a flow with a sessionStorage adapter and registers it globally — the flow rehydrates automatically on every page load.

## Events

Subscribe through `onEvent`:

- `flow.started`, `flow.completed`
- `step.entered` / `step.exited`
- `session.created`, `session.updated` (with `reason` and `diff`), `session.expired`, `session.recreated`
- `state.changed`
- `error` (discriminated by `source`: `session.create` / `session.update` / `session.recover` / `storage` / `router` / `guard` / `authenticate`)

## Migration from 1.x

The 2.0 rewrite removes the prescriptive UI components (`CioCheckout`, `useCheckoutSession`, `CheckoutTrigger`, `CheckoutOverlay`, `CheckoutInline`, `CheckoutStatus`) in favor of headless primitives. Every 1.x feature has an equivalent, mostly expressed through normal React with the new hook.
