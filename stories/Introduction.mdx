# Constructor Checkout UI

A headless checkout core with built-in Stripe, Fiserv and Shop Pay payment steps. The library runs the steps, the payment session, storage and routing. Your app renders the UI.

```bash
npm i @constructor-io/constructorio-ui-checkout
```

## Three integration paths, one core

| Path             | Best for                               | Entry                                                          |
| ---------------- | -------------------------------------- | -------------------------------------------------------------- |
| React            | React apps with the full flow          | `<CioCheckoutProvider provider="stripe">` + `useCioCheckout()` |
| Vanilla JS (npm) | Non-React SPAs or custom UIs           | `createCheckoutFlow(config)`                                   |
| Bundled script   | Server-rendered sites, `<script>` tags | `window.CioCheckout.resume(config)`                            |

All three wrap the same `createCheckoutFlow(config)` core.

## What the library owns

- **Steps.** A state machine with `start`, `next`, `back`, `goTo`, guards and optional steps.
- **Payment sessions.** Create, update, expire and recreate, with a queue so updates never overlap. `onCreateSession` is optional for providers that create their own session.
- **Session bootstrap.** `useCioCheckoutSession()` creates the session when a payment step mounts.
- **Cart.** A cart snapshot with debounced sync and a ready-made subtotal in `state.cartTotal`.
- **Payment in progress.** `flow.setPaymentInProgress(true)` blocks `back()` and `goTo()` while a charge runs.
- **Storage.** Opt-in. Pass a `storage` adapter to save and restore the flow. `storageKey` is optional.
- **Routing.** A router adapter keeps the URL and the current step in sync.
- **Built-in steps.** `<CioStripePaymentStep>`, `<CioFiservPaymentStep>` and `<CioShopPayPaymentStep>` with loading, error and confirm-error states, and `<CioFulfillmentStep>` with retry.
- **Translations.** Every built-in label can be replaced through `translations`.
- **Events.** Typed events for analytics and error reporting.

## What you own

- The button that opens checkout: style, placement and when it shows
- Cart, address, login, review and confirmation views, or any custom step
- Modal, inline or routed presentation
- Analytics, through the `onEvent` callback
