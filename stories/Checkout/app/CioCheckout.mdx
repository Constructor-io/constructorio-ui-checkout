# CioCheckout

A React component that wraps Stripe's Custom Checkout into a drop-in checkout experience with modal/inline display modes, fulfillment verification, and lifecycle callbacks.

Supports two Stripe surface modes via the `uiMode` prop:

- **`'elements'`** (default): Uses the GA Custom Checkout with `PaymentElement`. Full control over styling, field visibility, and the pay button.
- **`'form'`**: Uses the beta Checkout Form surface. Stripe manages the entire UI including the submit button. Requires Stripe to enable the beta on the account. Requires the `custom_checkout_payment_form_1` beta flag (handled internally by the library).

> **Server-side:** Both modes use `ui_mode: 'custom'` when creating the Checkout Session. The `uiMode` prop only affects the client-side Stripe.js surface.

### Behavior Notes

- **Billing details hidden in elements mode** — The `PaymentElement` renders with all billing detail fields (`name`, `email`, `phone`, `address`) set to `'never'`. Pre-fill customer details using the `defaultValues` prop instead.
- **Built-in error display** — When session resolution fails, the component renders an inline error `<div>` with `role="alert"` containing the error message. The `onError` callback still fires, but the error is also visible in the DOM without additional handling.
- **`triggerWhen` gates imperative open** — `triggerWhen` controls both trigger visibility _and_ the imperative `open()` method. If the condition returns `false`, calling `ref.current.open()` is a no-op.

## Session

The `session` prop tells the component how to get Stripe Checkout Session credentials (`clientSecret` and `publishableKey`).

### Direct object

Pass the session response directly if you already have it:

```tsx
<CioCheckout
  session={{
    clientSecret: 'cs_test_...',
    publishableKey: 'pk_test_...',
  }}
/>
```

### Async function

Pass a function that fetches the session from your backend. Called lazily when the customer clicks the trigger:

```tsx
<CioCheckout
  session={async () => {
    const res = await fetch('/api/checkout-session', { method: 'POST' });
    return res.json(); // { clientSecret, publishableKey }
  }}
/>
```

### Registry pattern

For non-React or multi-library setups, register a session globally and omit the `session` prop:

```ts
import { checkoutRegistry } from '@constructor-io/constructorio-ui-checkout';

checkoutRegistry.register(async () => {
  const res = await fetch('/api/checkout-session', { method: 'POST' });
  return res.json();
});
```

```tsx
<CioCheckout />
```

> **Note:** If a `session` prop is also provided, it takes precedence over the registry.

### Creating the Checkout Session (server-side)

Both `uiMode` values use `ui_mode: 'custom'` on the server. The difference between elements and form mode is entirely client-side.

```js
// Works for both elements and form mode
const session = await stripe.checkout.sessions.create({
  ui_mode: 'custom',
  mode: 'payment',
  line_items: [{ price: 'price_...', quantity: 1 }],
  return_url: 'https://example.com/order-confirm?session_id={CHECKOUT_SESSION_ID}',
});
// Return { clientSecret: session.client_secret, publishableKey }
```

> **Note:** Requires `stripe` Node SDK v18+ for `ui_mode: 'custom'` support.

#### Redirect behavior

For `ui_mode: 'custom'`, redirect behavior is controlled client-side by the Stripe.js SDK. Card payments complete in-place via the `onComplete` callback. Bank-redirect methods (iDEAL, Bancontact) navigate to `return_url`. The `return_url` is required when creating the session.

## Callbacks

```tsx
<CioCheckout
  session={mySession}
  callbacks={{
    onComplete: (event) => {
      // Payment succeeded. event.sessionId, event.items available.
    },
    onClose: () => {
      // User dismissed checkout without completing.
    },
    onError: (error) => {
      // Session creation or payment error.
    },
    onFulfill: async (event) => {
      // Verify fulfillment on your server. Return { success, message? }.
      const res = await fetch(`/api/verify/${event.sessionId}`);
      return res.json();
    },
    onFulfillComplete: (event) => {
      // Called after onFulfill resolves. event.result.success available.
    },
    onSessionExpired: () => {
      // Stripe session expired while form was open.
    },
  }}
/>
```

## Imperative Handle

Access `open`, `close`, and `reset` methods via a ref:

```tsx
import { useRef } from 'react';
import { CioCheckout } from '@constructor-io/constructorio-ui-checkout';
import type { CioCheckoutHandle } from '@constructor-io/constructorio-ui-checkout';

function App() {
  const checkoutRef = useRef<CioCheckoutHandle>(null);

  return (
    <>
      <button onClick={() => checkoutRef.current?.open()}>Open Checkout</button>
      <CioCheckout ref={checkoutRef} session={mySession} />
    </>
  );
}
```

          {props.isSubmitting
            ? 'Processing...'
            : `Complete Purchase ${props.amount}`}

### Checkout Status

Replace the post-payment fulfillment status UI:

```tsx
<CioCheckout
  session={mySession}
  componentOverrides={{
    checkoutStatus: {
      reactNode: (props) => (
        <div>
          {props.fulfillmentStatus === 'pending' && <p>Verifying...</p>}
          {props.fulfillmentStatus === 'fulfilled' && <p>Done!</p>}
          {props.fulfillmentStatus === 'failed' && (
            <button onClick={props.onRetry}>Retry</button>
          )}
          <button onClick={props.onDismiss}>Close</button>
        </div>
      ),
    },
  }}
/>
```

## Session Expiry

Checkout Sessions expire after 24 hours by default (configurable via `expires_at`).

When a session expires while the form is displayed, the component closes the UI and fires `onSessionExpired`:

```tsx
<CioCheckout
  session={mySession}
  callbacks={{
    onSessionExpired: () => {
      alert('Your session has expired. Please try again.');
    },
  }}
/>
```

To set a shorter expiry on the server:

```js
const session = await stripe.checkout.sessions.create({
  // ...
  expires_at: Math.floor(Date.now() / 1000) + 30 * 60, // 30 minutes
});
```

```tsx

  appearance={{

      colorBackground: '#ffffff',

  }}
/>

    variables: { fontFamily: 'Inter' },
  }}
/>
```
